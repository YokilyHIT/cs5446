# CS5446 GPU 与 NPU 双负责人研究同步


**建议分工：GPU 侧负责局部效用测量、数据口径和复测；NPU 侧利用稳定算力负责整局三臂验证，资源充足时再做方法扩展。两条主线共同构成项目交付。** “保证下限、探索上限”可以表达优先级。

## 共同研究问题

在 ALFWorld 文本环境中，固定 ReAct Planner 和一步 World Model，回答：

1. WM 的 confidence 与预测准确性、实际决策效用有什么关系？
2. 使用预测的收益中，有多少来自预测信息，有多少来自再次思考？
3. 在整局中持续使用预测，能否改善成功率，代价是多少？

当前固定模型为 Qwen3-4B-Instruct-2507。D0 是从 train 池中预先划出的开发游戏，用于测量和设计；当前没有微调基础模型。D1 原计划承担独立的局部效用验证；E 是整局评估使用的合格 unseen 游戏集合。

Proposal 中的 Utility Gate 是条件性扩展。项目可以交付有解释力的测量结果，并不以训练出一个优于基线的 Gate 为完成条件。

| 工作 | GPU  | NPU  |

| 整局验证 | 共同确定 E 资格、样本量、配对与统计口径，复核结果 | 主跑同一 NPU 配置下的 None/no_info/Always，保存逐游戏结果和成本 |

两人都对核心结果负责。稳定 NPU 的首要价值是提高必做实验的完成把握，其次才是扩大实验量。GPU 侧保留必要的输入、状态、计数和配置检查。

## 局部实验方法

从固定 None 策略访问的 D0 状态选点。恢复相同环境状态、历史和剩余预算后：

| 分支 | 当前步怎么做 | 回答的问题 |
|---|---|---|
| D | 直接执行原 draft 动作 | 原始决策基线 |
| N | 再决策一次，但不提供 WM 预测 | 再次思考的作用 |
| P | 提供 WM 预测后再决策 | 预测参与决策的作用 |

**只在当前步施加干预，之后三条分支都使用同一 None 策略继续。** 已执行 t 步时，每条分支剩余总动作预算为 30−t。每个物理组只采一次续跑，即 r=1；符合冻结共享条件的分支共用一次物理续跑，统计时仍按原状态计数。

三种单次观测差分别为 P−D（接纳）、P−N（信息）和 N−D（再决策）。它们是对应期望效用的观测，不能把一个状态的一次差值当作已知真实效用。

预测准确性使用 **D 执行 draft 后的真实第一步观察**作为参考，不能拿 P 改选动作后的观察评分。confidence 使用原 mean logprob 排序，exp 分数只用于展示；它不是校准后的成功概率。EM/token-F1、同分和案例规则沿用已定实现。

每游戏原始权重为 1/24，状态权重为 1/(24×原 k_j)。3 个源失败点保留在计划与失败分母中，局部 Y 和效用保持缺失；按既定规则判定的分支策略失败则是 Y=0。各指标注明自己的可用分母，不能把缺失补零或删点后重新按每局剩余状态平权。

N/P 抽查是对固定首动作之后的续跑做有界复测，用于检查测量可信度。它不是新的方法对照，也不重新挑选 D0。

## 整局实验方法

建议由 NPU 负责人主跑 E 上的三臂配对评估：每个合格游戏都运行以下三个策略，**单次尝试、动作上限 30，主指标 SR@30**。

| 策略 | 整局中的决策方式 |
|---|---|
| None | 各步执行基础 ReAct 决策 |
| no_info | 各步按既定协议增加不看预测的再决策 |
| Always | 各步按既定协议使用 WM 预测再决策；不可用预测按已定 fallback 处理 |

主对比是 **Always−no_info**，用于考察预测信息在额外再决策之外的作用；同时报告 Always−None 与 no_info−None。按游戏配对报告成功率差、成功转失败和失败转成功、失败/缺失以及调用、tokens、时间。使用共同定义的逐游戏结果，不只比较两列总成功数。

与局部实验不同，这里每一步都按所属策略决策；因此 D0 局部观测稀疏不能替代整局实验。

正式运行前，两人共同写定 E 的游戏清单和资格、固定样本量、三臂顺序及分作业方式、失败/重试规则和区间方法。E 不用于选阈值、挑模型或决定要跑哪些游戏；技术验收和调参使用开发游戏。旧统计中的 134 和资产盘点的 255 口径尚未统一，应先对齐实际 ID 和历史使用，不能直接把任一数字当作最终 E 样本量。

GPU 原方案指定了整卡 A100；若改由 NPU 主跑 E，需要在查看 E 结果前记录这项部署修订。三臂在同一固定 NPU 部署内比较，模型版本、prompt、解析、预算、memory 和失败规则保持一致。后端、硬件、精度等实际差异如实记录，GPU 与 NPU 结果按部署分别报告，不直接合成一个同配置样本。

移植范围是研究策略与日志契约，不要求复制全部 GPU Slurm、cgroup 和历史恢复包装层。NPU 只需实现其平台实际需要的资源检查和结果保存，并完成小范围端到端验收。

## Gate 与后续扩展

当前 68 个有效局部点的接纳差异过于稀疏，暂不把训练 Utility Gate 放在关键路径。若之后有足够的效用变化、独立验证样本和时间，再明确新增开发数据、特征、训练及验证方案。

需要区分两个问题：

- Proposal 的**预测后接纳 Gate**：预测已经生成，可用 confidence 和预测特征；拒绝预测也已经支付本次 WM 成本。
- 队友路线提出的**调用前 Gate**：决定是否调用 WM；不能使用尚未生成的预测及其 confidence，成本目标也不同。

两者都可以研究，但不能仅改名称就共用效用标签或宣称节省相同成本。额外在线 Random/Confidence、约 200 个困难状态、best-of-5 或第二模型，也不自动成为当前必做项。

## 这次同步要确定的四件事

1. **接受上述两人分工吗？** GPU 完成局部测量闭环；NPU 主跑整局三臂，扩展排在核心实验之后。
2. **局部 A 的交付层级如何定？** 当前建议以 D0 开发期诊断交付、暂缓大规模确认性 D1。若接受，明确这是对原验证范围的缩减；不能声称已完成独立 confidence—效用验证。若坚持 D1，再依据稀疏结果规划样本量与精度。
3. **哪些 unseen 游戏仍有资格用于 E？** 先交换历史使用记录，再固定清单、规模和 NPU 实际配置。
4. **先统一哪些接口？** 两人先核对策略定义、输入清单、失败语义、逐游戏日志和一组开发期样例；一致后再把明确的数据分析任务交给其他成员。

NPU 的历史使用整理、开发期运行适配可以和 GPU 的 D0 报告并行。正式 E 开始前，应完成共同协议与必要的测量复核；这些准备工作不要求重跑 D0-var。
