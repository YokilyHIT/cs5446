# ALFWorld Pre-Experiments (NPU build)

Reproducible implementation of the two pre-experiments from
`两个方向_预实验设计_ClaudeCode可复现版.md`:

- **Experiment A — Selective Failure Learning**: do different failure-derived
  lessons have significantly different real value for future tasks?
- **Experiment B — Prediction Confidence vs Planning Utility**: does a
  world-model's self-reported confidence actually predict whether acting on
  its foresight helps or hurts planning?

Agent: ReAct-style ALFWorld agent driven by `Qwen/Qwen3-4B-Instruct-2507`
through a local vLLM OpenAI-compatible server.

**This code was authored on a machine with no GPU/NPU.** The LLM-serving
half of the pipeline is meant to run on a separate **Huawei Ascend NPU**
host — see **[README_NPU_SETUP.md](README_NPU_SETUP.md)** for the full
environment + dataset setup (CANN/torch_npu/vLLM-Ascend install, ALFWorld
dataset download, AdaMEM checkout, model download, starting the server, and
the mandatory smoke tests) before running anything here.

## Quick start (on the NPU host)

```bash
bash scripts/setup_env_npu.sh
MODEL_PATH=$HOME/models/Qwen3-4B-Instruct-2507 bash scripts/start_vllm_npu.sh &
python scripts/inspect_alfworld_api.py
bash scripts/run_all.sh
```

does, every environment variable it reads, and the troubleshooting guide.

## Design notes

- Every fixed prompt, sampling parameter, seed list, and split name is
  copied verbatim from the spec into `preexperiments/configs/*.yaml` and
  `preexperiments/common/prompts.py` — no script hard-codes its own copy.
- `preexperiments/common/replay_state.py::restore_state` is the only
  sanctioned way to reproduce a specific ALFWorld state twice (spec section
  19); it is used to run Branch 0 / Branch W counterfactual rollouts from
  the exact same decision point in Experiment B.
- Every `analyze.py` rebuilds its summary purely from on-disk JSONL/CSV, so
  the pipeline's headline numbers are independently reproducible from the
  raw logs alone (spec section 37, test 7) — verified by
  `preexperiments/tests/test_analysis_rebuild.py`.
- Go/No-Go verdicts only ever use the phrasing "supported by preliminary
  evidence" / "weakly supported" / "not supported under the current setup"
  (spec section 43) — never "hypothesis proven".
